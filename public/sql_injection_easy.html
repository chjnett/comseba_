DB와 DBMS, 기본부터

SQL을 배우기 전에 딱 두 단어만 구분하면 됩니다. 데이터베이스(DB)는 "데이터가 저장된 창고" 그 자체이고, DBMS(DataBase Management System)는 그 창고를 운영하는 "관리 시스템(소프트웨어)"입니다. MySQL, PostgreSQL, Oracle, MSSQL, SQLite 같은 게 모두 DBMS입니다.

비유로 이해하기

DB는 도서관 건물과 책장 자체, DBMS는 그 도서관을 운영하는 사서 시스템입니다. 우리는 책장에 직접 손을 넣어 책을 꺼내지 않고, 항상 사서(DBMS)에게 SQL이라는 요청서로 부탁합니다. 웹 애플리케이션도 마찬가지로 직접 데이터 파일을 건드리지 않고 DBMS를 거쳐 데이터를 읽고 씁니다.

지금 우리가 다루는 건 그중에서도 관계형 DBMS(RDBMS)입니다. 데이터를 엑셀 시트처럼 행(row)과 열(column)로 이루어진 테이블에 저장하고, 테이블 간의 "관계"를 통해 데이터를 연결합니다.

용어엑셀로 치면설명
테이블(Table)시트(Sheet)users, posts 처럼 같은 종류의 데이터를 모아둔 단위
컬럼(Column)열(세로줄)id, pw, email 처럼 각 데이터의 속성
로우(Row)행(가로줄)실제 데이터 한 건. 회원 한 명, 게시글 한 개 등
스키마(Schema)워크북 전체 구조테이블/컬럼 구성을 정의한 설계도
왜 이게 SQL Injection에서 중요할까?

공격자가 결국 노리는 건 이 "창고 안의 데이터"입니다. 그리고 우리가 사서(DBMS)에게 보내는 요청서(SQL)를 조작할 수 있다면, 사서는 그게 진짜 관리자의 요청인지 공격자의 요청인지 구분하지 못하고 그대로 따릅니다. 이게 SQL Injection의 본질입니다.

1

기본 SQL 문법, 표로 한눈에 정리

뒤에서 하나씩 다시 자세히 설명하겠지만, 먼저 표로 전체 그림을 잡아두면 이후 내용이 훨씬 잘 들어옵니다. 처음 보면 외울 필요 없고, 실습하다 막힐 때 다시 와서 찾아보는 표로 써도 충분합니다.

① 데이터 조회 — SELECT 문 구조

전체 골격SELECT 컬럼 FROM 테이블
WHERE 조건
ORDER BY 컬럼 ASC|DESC
LIMIT 개수;
키워드의미예시
SELECT *모든 컬럼 조회SELECT * FROM users
FROM어느 테이블에서FROM users
WHERE조건에 맞는 행만WHERE id='kim'
ORDER BY정렬 기준ORDER BY id DESC
LIMIT결과 개수 제한LIMIT 5

연산자의미예시

2

SQL이 뭔가요?

SQL(Structured Query Language)은 데이터베이스에 "이것 좀 보여줘 / 바꿔줘 / 지워줘"라고 말 거는 언어입니다. 우리가 웹사이트에서 로그인하거나 게시글을 검색할 때, 그 뒤에서는 항상 SQL 문장이 만들어지고 있습니다.

비유로 이해하기

데이터베이스를 거대한 도서관이라고 생각해보세요. SQL은 사서에게 "역사책 코너에서 1990년 이후 출간된 책을 다 가져다줘"라고 말하는 요청서 같은 겁니다. 그 요청서의 양식이 곧 SQL 문법입니다.

3

제일 많이 쓰는 SELECT

SQL Injection 문제 대부분은 결국 SELECT 문 하나를 어떻게 비틀어보는가의 게임입니다. 기본형은 이렇게 생겼습니다.

기본 형태SELECT 보고싶은컬럼 FROM 테이블 WHERE 조건;

예를 들어 회원 목록에서 아이디가 kim인 사람만 보고 싶다면:

SELECT * FROM users WHERE id = 'kim';

여기서 가장 중요한 부분은 WHERE입니다. WHERE 뒤에 적힌 조건이 참(true)인 행만 보여준다는 것, 이거 하나만 기억하면 절반은 이해한 겁니다.

4

데이터를 바꾸는 SQL — DML

지금까지 본 SELECT는 데이터를 "조회"만 합니다. 데이터를 새로 넣거나(INSERT), 고치거나(UPDATE), 지우는(DELETE) 명령어들을 묶어서 DML(Data Manipulation Language)이라고 부릅니다. Dreamhack의 'SQL DML' 강의가 다루는 부분이 바로 이거예요.

새 회원 추가INSERT INTO users (id, pw) VALUES ('kim', '1234');
비밀번호 수정UPDATE users SET pw='new1234' WHERE id='kim';
회원 삭제DELETE FROM users WHERE id='kim';
왜 이게 SQLi에서 중요할까?

여기서도 똑같이 WHERE가 핵심입니다. 만약 회원 삭제 기능에 SQL Injection이 가능하다면, WHERE 조건이 무력화되어 회원 전체가 삭제되는 끔찍한 사고로 이어질 수 있습니다. SELECT에서의 정보 유출보다 더 치명적인 경우가 많아요.

5

SQL의 강력한 기능들 — Subquery & UNION

Dreamhack의 'SQL Features' 강의에서 다루는 두 기능, 서브쿼리와 UNION은 SQL Injection 심화 공격(Subquery-based, Union-based)의 재료가 됩니다.

서브쿼리: 쿼리 안에 또 다른 쿼리

SELECT uid FROM users
WHERE id = (SELECT id FROM users WHERE uid='admin');

괄호 안의 쿼리가 먼저 계산되어 그 결과를 바깥 쿼리에 넘겨줍니다. SQL Injection에서는 이 괄호 안에 (SELECT pw FROM users LIMIT 1) 같은 걸 끼워 넣어서, 원래는 보이지 않던 다른 컬럼의 값을 조건문 안으로 끌고 오는 통로로 씁니다.

UNION: 두 결과를 이어붙이기

뒤에서 곧 자세히 다룰 UNION-based 공격의 재료입니다. 미리 한 가지만 기억해두면 좋습니다 — UNION으로 합치려는 두 SELECT는 컬럼 개수가 정확히 같아야 동작한다는 것. (6번 섹션에서 바로 실습해봅니다.)

6

로그인은 어떻게 동작할까?

로그인 폼에 아이디/비밀번호를 입력하면, 서버는 보통 이런 식으로 SQL 문장을 "조립"합니다.

서버가 하는 일 (의사 코드)query = "SELECT * FROM users WHERE id='" + 입력한아이디 + "' AND pw='" + 입력한비밀번호 + "'"

아이디에 kim, 비밀번호에 1234를 넣으면 완성되는 문장은:

SELECT * FROM users WHERE id='kim' AND pw='1234'

이 결과가 1줄이라도 나오면 "로그인 성공", 0줄이면 "로그인 실패"인 거죠. 여기까지 이해하셨다면, 다음 섹션에서 이걸 어떻게 속이는지 바로 보입니다.

7

SQL Injection이 통하는 이유

핵심 아이디어 단 한 줄: 입력값에 따옴표(')를 넣으면, 서버가 "조립"한 SQL 문장의 구조를 내가 바꿀 수 있다.

아이디 입력칸에 평범한 아이디 대신 이런 값을 넣어볼게요.

입력값admin'--

그러면 서버가 조립한 문장은 이렇게 됩니다.

SELECT * FROM users WHERE id='admin'--  ' AND pw='아무거나'
왜 이게 되는 걸까?

SQL에서 --는 "이 뒤는 전부 무시해(주석)"라는 뜻입니다. 그래서 admin'--를 넣으면 ① 내가 연 따옴표가 원래 있던 따옴표와 짝이 맞춰지고, ② 그 뒤의 AND pw=... 부분이 통째로 주석으로 사라집니다. 결국 서버는 "id가 admin인 사람 있어?"만 묻게 되고, 비밀번호 검사 자체가 실행되지 않습니다.

자주 막히는 부분 MySQL은 -- 뒤에 공백이 최소 1칸 있어야 주석으로 인식합니다. admin'--가 안 되면 admin'-- (마지막에 스페이스바!)로 다시 시도해보세요.
8

첫 페이로드 만들어보기

로그인 우회의 또 다른 유명한 방법은 "항상 참"으로 만드는 것입니다.

입력값 (아이디 칸에)' OR '1'='1
완성되는 쿼리SELECT * FROM users WHERE id='' OR '1'='1' AND pw='아무거나'

'1'='1'은 항상 참이고, OR로 연결되어 있으니 앞의 id=''가 거짓이어도 전체 조건이 참이 됩니다. → 조건을 통과해 전체 행이 결과로 나옵니다.

실습 힌트 Dreamhack 로그인 우회 문제에서 안 될 때는, 입력값이 정확히 ' -- 같은 특수문자를 포함해서 전송되는지 개발자도구(Network 탭)로 실제 전송된 요청을 꼭 확인해보세요. 프론트엔드에서 특수문자를 막거나 트리밍하는 경우가 있습니다.
9

UNION으로 데이터 훔쳐보기

로그인 우회는 "통과/실패"만 알려주지만, 검색 결과처럼 화면에 데이터가 그대로 출력되는 페이지에서는 더 재미있는 일을 할 수 있습니다. UNION은 두 개의 SELECT 결과를 위아래로 이어붙이는 명령어입니다.

  1. ① 컬럼 개수 맞추기

    UNION은 두 SELECT의 컬럼 개수가 같아야 동작합니다. ORDER BY 1, ORDER BY 2... 숫자를 늘려가며 에러가 나는 지점을 찾으면 원래 컬럼 개수를 알 수 있습니다.

    ?id=1 ORDER BY 3  // 에러 발생 → 컬럼은 2개

  2. ② 화면에 보이는 자리 찾기

    존재하지 않는 값(예: -1)으로 원래 결과를 비우고, 그 자리에 숫자를 하나씩 넣어 어디가 화면에 출력되는지 확인합니다.

    ?id=-1 UNION SELECT 1,2  // 화면에 '1'과 '2' 중 뭐가 보이나요?

  3. ③ 진짜 원하는 데이터 넣기

    화면에 보이는 자리에 테이블/컬럼 이름, 그리고 실제 데이터를 차례로 넣어봅니다.

    ?id=-1 UNION SELECT table_name,2 FROM information_schema.tables
?id=-1 UNION SELECT uid,pw FROM users
비유로 이해하기

information_schema는 "이 도서관에 어떤 서가(테이블)가 있고, 각 서가에 어떤 분류표(컬럼)가 붙어있는지" 알려주는 안내 책자입니다. 테이블/컬럼 이름을 모를 땐 여기서부터 시작하세요.

10

눈 감고 찾기, Blind SQLi

화면에 데이터가 직접 보이지 않고, "성공/실패" 또는 "있음/없음" 정도만 알 수 있는 문제도 많습니다. 이럴 땐 스무고개 하듯 한 글자씩 맞춰갑니다.

"현재 DB 이름의 첫 글자가 a인가?"를 묻는 쿼리?id=1 AND SUBSTRING(database(),1,1)='a'

참이면 평소처럼 화면이 뜨고, 거짓이면 다르게 동작합니다. 이걸 a, b, c... 순서로(또는 이진탐색으로 더 빠르게) 시도하면서 한 글자씩 알파벳을 찾아냅니다. 화면 차이도 없다면 시간차를 이용합니다.

참일 때만 5초 늦게 응답?id=1 AND IF(SUBSTRING(database(),1,1)='a', SLEEP(5), 0)
막혔을 때 Blind SQLi는 한 글자씩 손으로 맞추면 너무 오래 걸립니다. 원리를 한 번 손으로 해보고 이해했다면, Python requests로 알파벳을 순회하는 짧은 스크립트를 짜는 쪽이 훨씬 빠르고, 이후 자동화 도구(sqlmap)를 이해하는 데도 도움이 됩니다.

막혔을 때 체크리스트

증상확인해볼 것
페이로드를 넣어도 반응이 없다주석 뒤 공백(-- ), URL 인코딩(' → %27) 여부 확인
로그인 우회가 안 된다아이디/비밀번호 둘 다 시도했는지, 괄호로 감싸진 쿼리인지(WHERE (id=...)) 확인
UNION 시도 시 계속 에러컬럼 개수가 맞는지, 각 컬럼의 데이터 타입이 호환되는지(숫자 자리에 문자열 넣으면 에러)
Blind 결과가 매번 똑같다참/거짓일 때 화면이 정확히 어떻게 다른지부터 먼저 재확인 (에러 페이지? 빈 화면? 다른 문구?)
아무것도 안 통한다입력값이 숫자형 컬럼인지 문자형 컬럼인지 확인 — 숫자형이면 따옴표 없이 1 OR 1=1 형태로 시도

개발자라면 이렇게 막아요

공격을 이해했다면, 막는 방법도 함께 알아두면 훨씬 오래 기억에 남습니다. 결론은 하나입니다: 입력값을 절대 SQL 문장에 직접 끼워 넣지 않는다.

❌ 위험한 방식
query = "SELECT * FROM users WHERE id='" + id + "'"
✅ 안전한 방식 (Prepared Statement)
stmt = conn.prepare("SELECT * FROM users WHERE id=?")
stmt.bind(id)

Prepared Statement를 쓰면 입력값이 "SQL 문장의 일부"가 아니라 항상 "그냥 데이터"로만 취급되기 때문에, 아무리 따옴표나 주석을 넣어도 쿼리 구조 자체가 바뀌지 않습니다.

한 줄 정리

문자열 조립 = 요청서 빈칸에 글씨를 적는 게 아니라 요청서 양식 자체를 고쳐 쓸 수 있게 둔 것. Prepared Statement = 빈칸에 뭘 적든 양식은 절대 안 바뀌게 만든 것.
